# recordlife — 설계 문서

- 작성일: 2026-11-20
- 상태: 승인 대기
- 디자인 기준: [DESIGN.md](../../../DESIGN.md) (폰트, 색, 간격, 모션은 전부 여기를 따른다)

## 1. 의도

지금 이 순간 내가 뭘 하고 있는지 한 줄로 적고, 끝나면 종료해서, 하루가 **시간 블록**으로 남게 한다.
사용자는 나 혼자다. 화면에 이것저것 보이는 걸 싫어하므로 **입력칸 하나로 시작하는 극단적으로 단순한 화면**이 핵심이다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 입력하고 시작하면 그 순간부터 시간이 기록된다.
- 새로고침, 브라우저 종료, 다른 기기에서 열어도 진행 중인 기록이 그대로 이어진다.
- 종료하면 기록으로 남는다.
- 일별 보기: 몇 시부터 몇 시까지 뭘 했는지 시간 블록으로 보여 주고, 기록 없는 시간은 빈칸으로 둔다.
- 월별 보기: 날마다 작은 원 하나. 기록 시간이 많을수록 색이 진하다.
- 집 노트북에 `docker compose up -d` 한 줄로 띄우고, VPN(Tailscale 등)으로 폰과 PC에서 접속한다.

**비목표 (지금은 안 함)**
- 태그, 카테고리, 프로젝트 분류
- 주간 보기
- 통계, 차트, 리포트
- 여러 사용자, 회원가입, 로그인
- 사진, 기분, 위치 (예전 일기 미리보기에 있던 요소는 쓰지 않는다)
- 오프라인 동작, 푸시 알림, 자동 백업

**안티목표 (이러면 실패)**
- 첫 화면에 입력칸과 진행 중 기록 외의 정보가 보인다.
- 새로고침이나 기기 전환 후 진행 중인 시간이 0으로 돌아가거나 사라진다.
- 시작하는 데 두 번 이상 탭해야 한다 (입력 → Enter 또는 시작 버튼 한 번).

## 3. 제약

- 단일 사용자. VPN이 보안 경계이므로 앱 자체 인증은 없다.
- 노트북에서 가볍게 돌아야 한다: 컨테이너는 앱 1개 + DB 1개.
- 폰과 PC 둘 다 쓰므로 반응형 (모바일 기준 390px, 데스크톱은 중앙 컬럼 max 640px).
- 시간은 DB에 UTC(`timestamptz`)로 저장하고, 화면과 날짜 경계는 **Asia/Seoul** 기준으로 계산한다. 노트북 시간대 설정에 의존하지 않는다.

## 4. 만드는 방법 (검토한 대안)

| 안 | 구성 | 장점 | 대가 |
|---|---|---|---|
| **A (선택)** | React(Vite) + Hono(Node) + PostgreSQL | 전부 TypeScript, 타입 공유. Hono가 빌드된 화면도 서빙해서 컨테이너 2개. 가장 가벼움 | 라우팅/빌드 설정을 직접 조금 잡아야 함 |
| B | Next.js + PostgreSQL | 프로젝트 하나 | 서버 컴포넌트/캐싱 등 이 앱에 과한 기능, 빌드와 메모리가 무거움 |
| C | React(Vite) + FastAPI + PostgreSQL | 백엔드 코드가 짧음 | 언어 2개, 타입 이중 정의, 컨테이너 3개 |

**사용자가 A를 골랐다.** 이유: "스프링부트처럼 빡세지 않게"라는 조건에 가장 잘 맞고 노트북에서 가장 가볍다.

## 5. 사용자가 정한 것

- 첫 화면은 입력칸 하나. 태그 없음. 입력하고 시작하면 시작 시각이 기록된다.
- F5나 브라우저 종료 후에도 진행 중 시간이 유지된다.
- 종료하면 기록으로 남는다.
- 보기는 일별(상세 시간 블록, 빈 시간은 여백)과 월별(날마다 원, 많이 할수록 진함) 두 가지. 주간은 없다.
- 백엔드는 가볍게, DB는 docker-compose로.
- 사용자는 본인 혼자, 집 노트북 + VPN으로 접속.
- 기술 구성은 A안.

## 6. 동작 설계

### 6.1 기록 규칙
- **진행 중인 기록은 한 번에 하나만.** (Claude 판단) 진행 중에 새 활동을 시작하면 이전 기록을 그 시각으로 자동 종료하고 새 기록을 시작한다. 일을 바꿀 때 종료를 따로 누를 필요가 없다.
- 이름은 앞뒤 공백 제거 후 1–100자. 빈 입력이면 시작 버튼 비활성.
- 저장 정밀도는 초 단위, 기록 목록 표시는 분 단위(`09:12–10:36`, `1시간 24분`). 진행 중 타이머만 초까지 보여 준다(`1:24:07`).
- **진행 중 시간은 서버의 `started_at`과 현재 시각의 차로 계산한다.** 클라이언트에 상태를 저장하지 않으므로 새로고침, 기기 전환과 무관하게 이어진다. 탭이 다시 보이게 될 때(`visibilitychange`, `focus`) 서버에서 다시 불러와 다른 기기에서 바꾼 내용도 반영한다.

### 6.2 수정 / 삭제 (Claude 판단)
- 종료를 깜빡하면 긴 블록이 생기므로, 일별 보기에서 블록을 누르면 바텀 시트가 열리고 **이름, 시작 시각, 종료 시각을 고치거나 삭제**할 수 있다.
- 진행 중 기록도 이름과 시작 시각을 고칠 수 있다(종료 시각 없음).
- 검증: 종료 > 시작, 시작/종료는 미래일 수 없음. **겹치는 기록은 허용한다** (자동 조정하지 않음, 일별 보기에서 나란히 표시). 이유: 수정할 때마다 다른 기록이 바뀌면 혼란스럽다.
- 지나간 시간에 기록을 새로 추가하는 기능은 이번 범위에 넣지 않는다 (필요하면 다음 단계).

### 6.3 날짜 경계
- 하루는 Asia/Seoul 00:00–24:00.
- 자정을 넘긴 기록은 **양쪽 날에 잘라서** 각각 보여 준다. 데이터는 한 행 그대로다.

## 7. 화면

내비게이션은 상단 좌측 워드마크, 우측 작은 세그먼트 `지금 · 일 · 월` 하나뿐 (Claude 판단: 하단 탭바보다 덜 눈에 띄고 데스크톱에서도 자연스럽다).

### 7.1 지금 (`/`)
```
recordlife                 [지금|일|월]

  ┌─────────────────────────────┐
  │ 지금 뭐 하고 있나요?          │   ← 입력칸, 자동 포커스
  └─────────────────────────────┘
               [ 시작 ]               ← Ember 버튼, Enter로도 시작

  ─── 진행 중일 때 ───
  회사 이슈 처리                       ← 세리프(마루부리) 제목
  1:24:07                             ← 큰 tabular 숫자, 1초마다 갱신
  09:12 시작
               [ 종료 ]
  (아래에 입력칸이 남아 있어 바로 다음 일로 전환 가능)
```
- 진행 중이 아닐 때는 입력칸과 시작 버튼만 보인다.
- 오늘 기록 목록 같은 부가 정보는 보여 주지 않는다.
- 브라우저 탭 제목에 진행 중인 활동과 경과 시간을 보여 준다 (`1:24 회사 이슈 처리`).

### 7.2 일 (`/day/:yyyy-mm-dd`, 기본은 오늘)
```
‹  11월 20일 금요일  ›          총 6시간 40분
00 │
.. │
09 ├──────────────────────
   │ 회사 이슈 처리  09:12–10:36
10 │
   ├──────────────────────
11 │                         ← 빈 시간은 그냥 여백
12 │ 점심  12:05–12:50
```
- 세로 24시간 타임라인. 1시간 = 56px (Claude 판단). 처음 열면 첫 기록 위치, 오늘이면 현재 시각으로 스크롤.
- 블록 높이 = 실제 시간 비율. 짧아서 글이 안 들어가면 (약 20분 미만) 이름만 한 줄로 줄인다.
- 진행 중 블록은 현재 시각까지 늘어나고 Ember 테두리로 표시. 현재 시각 가로선(Ember).
- 겹치는 블록은 가로로 나눠 나란히 배치.
- 좌우 화살표/스와이프로 날짜 이동. 미래 날짜로는 이동 안 함.

### 7.3 월 (`/month/:yyyy-mm`, 기본은 이번 달)
```
‹  2026년 11월  ›
일 월 화 수 목 금 토
 ·  ●  ◉  ●  ○  ◉  ·
...
```
- 7열 달력, 날마다 원 하나. 원 아래(또는 안)에 날짜 숫자.
- **진하기 = 그날 기록된 총 시간** 5단계 (Claude 판단): 0 / ~2시간 / ~4시간 / ~6시간 / 6시간 이상 → Ember 0%(빈 원 테두리) / 25% / 50% / 75% / 100%.
- 오늘은 원 테두리 강조. 미래 날짜는 흐리게.
- 원을 누르면 그날의 일별 보기로 이동.

## 8. 기술 설계

### 8.1 구조
```
recordlife/
  docker-compose.yml        # app + db
  Dockerfile                # 멀티스테이지: web 빌드 → server가 정적 파일 서빙
  .env.example
  server/                   # Hono API (Node 22)
  web/                      # React + Vite
  shared/                   # 타입, 날짜 계산 유틸 (양쪽에서 사용)
```
- 패키지 매니저: pnpm workspace (Claude 판단).
- ORM / 마이그레이션: Drizzle ORM + drizzle-kit. 앱 시작 시 마이그레이션 자동 실행.
- 프론트: React Router, 데이터 요청은 fetch + 얇은 훅 (상태 라이브러리 없음). 날짜 계산은 `date-fns` + `date-fns-tz`.
- 스타일: CSS 변수로 DESIGN.md 토큰을 그대로 옮긴 순수 CSS (Tailwind 등 미사용, Claude 판단: 토큰 수가 적고 미리보기 HTML의 CSS를 그대로 재사용할 수 있다).
- 폰트: Pretendard, 마루부리. 우선 CDN, self-host는 다음 단계.

### 8.2 데이터 모델
```sql
create table activities (
  id          uuid primary key default gen_random_uuid(),
  title       text not null check (char_length(title) between 1 and 100),
  started_at  timestamptz not null,
  ended_at    timestamptz,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now(),
  check (ended_at is null or ended_at > started_at)
);
-- 진행 중 기록은 최대 1개
create unique index one_running on activities ((true)) where ended_at is null;
create index activities_started_at on activities (started_at);
```

### 8.3 API (`/api`, JSON)
| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | `/api/current` | 진행 중 기록 1개 또는 `null` |
| POST | `/api/activities/start` | `{title}`. 진행 중 기록이 있으면 같은 트랜잭션에서 지금 시각으로 종료 후 새로 시작 |
| POST | `/api/activities/:id/stop` | 지금 시각으로 종료 |
| PATCH | `/api/activities/:id` | `{title?, startedAt?, endedAt?}` 수정 |
| DELETE | `/api/activities/:id` | 삭제 |
| GET | `/api/days/:date` | 그날(Asia/Seoul)과 겹치는 기록 목록 |
| GET | `/api/months/:yyyy-mm` | 날짜별 총 기록 분 `{ "2026-11-20": 400, ... }` (자정 넘김은 날별로 잘라 합산, 진행 중은 현재까지) |

- 시작/종료 시각은 **서버 시각**을 쓴다 (기기마다 시계가 달라도 일관).
- 오류는 `{error: string}` + 적절한 상태 코드.

### 8.4 배포
- `docker-compose.yml`: `db`(postgres:17, 이름 있는 볼륨), `app`(Node, 포트 `3000`), `restart: unless-stopped`.
- 설정은 `.env` (`DATABASE_URL`, `PORT`).
- 노트북에서 `docker compose up -d --build`. 접속은 `http://<노트북 VPN 주소>:3000`.
- README에 Tailscale 연결과 `tailscale serve`로 HTTPS 붙이는 방법을 짧게 적는다.

### 8.5 테스트
- 서버: Vitest + 실제 Postgres(테스트용 compose 서비스)로 API 통합 테스트. 특히 자동 종료, 진행 중 1개 제약, 자정 분할, 월별 합산, Asia/Seoul 경계.
- `shared`의 날짜 계산 유틸 단위 테스트.
- 프론트: 핵심 흐름(시작 → 새로고침 → 시간 유지 → 종료) 수동 확인 + 브라우저로 화면 점검.
